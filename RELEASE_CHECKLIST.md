# Release and submission checklist

The GitHub documentation and working datasets are public research materials. Before describing the complete project as final, verify:

- [ ] Read the original four official notices yourself and confirm each focal numerical proposition.
- [ ] Reopen the three disputed news links and confirm the precise current wording and publication/update dates.
- [ ] Inspect both CSVs. Distinguish 12 purposive diagnostic records from ten retrospective event/outlet slots; **four article URLs overlap**.
- [ ] Run `python tools/verify_corpus.py` and `python -m unittest discover -s tests -v`.
- [ ] Confirm your **own** role in the project's concept, framing, verification and final decisions. Read and approve [AI disclosure](AUTHORS_AND_AI.md).
- [ ] Check institution/internship rules on AI-assisted research, the writing of applications and sharing manuscripts publicly.
- [ ] Review final report details, bibliography, title page and approval status.
- [ ] Upload the PDF if and only if you are comfortable releasing it with accurate 'working draft' labeling; see [report/README.md](report/README.md).
- [ ] Check all links on an unauthenticated browser before placing them on a CV.
- [ ] For a future peer-reviewed publication, preregister or transparently describe selection, archive sources, seek independent coding, and evaluate standards-based baselines.
